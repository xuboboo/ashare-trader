# 数据源、级别与延迟

一句话：**这套系统看到的是 L1 三秒快照，不是 L2 逐笔**。所有关于"能不能做盘中"的判断都由此决定。

## 级别：L1

| 有 | 没有 |
| --- | --- |
| 最新价、买五档 / 卖五档 | 十档全量 |
| 当日累计成交量、成交额 | 逐笔成交（每笔的方向、价、量） |
| 分时均价 VWAP、量比、换手率 | 逐笔委托 / 委托队列（买一后面排了多少手） |
| 涨跌停价、总市值 / 流通市值 | 盘口委托变化的推送 |
| 日线 OHLCV、涨停池、连板数 | 分钟级以下的可靠路径 |

交易所 L1 本身就是 **3 秒一个切片**，这是物理下限，与本机网络、代码效率无关。
平均信息年龄 ≈ 1.5s，最差 3s，再叠加第三方接口的抓取与转发。

## 三个踩过的坑（都有测试或代码兜住）

1. **GBK**：腾讯返回 `charset=GBK`，直接 `res.text()` 会变乱码。`http.ts` 按 `content-type`
   判断编码，用 `TextDecoder("gbk")`（Bun 1.4.2 支持）。
2. **`000001` 歧义**：东财 secid `1.000001` 是上证指数、`0.000001` 是平安银行。用代码前缀推市场
   会把大盘 MA5 算成银行股价格（真踩过）。所有大盘相关一律用 `INDEX_SECID = "1.000001"`。
3. **限流**：`push2his` 在持续 ~2 req/s 后会整体 `ECONNRESET`，且之后连之前成功的代码也失败。
   对策：全局降到 3 req/s + 抖动退避 + **三源回退** + 东财失败后 2 分钟熔断。
   回退源没有成交额，用 `(高+低+收)/3 × 成交量` 估算并打 `amountEst` 标记，
   `fetch-daily` 与 `backtest` 都会报出"多少支是估算的"。

字段序号由 `test/quotes.test.ts` 用 **2026-09-18 真实录制的一行行情**锁死（契约测试）：
上游改字段顺序时测试先炸，而不是让因子静默算错。关键位置：腾讯 `47/48` = 涨跌停价、
`49` = 量比、`51` = 分时均价、`37` = 成交额（**万元**）；东财 `stock/get` `f51/f52` = 涨跌停价；
kline `fields2` 顺序 = 日期,开,收,高,低,量,额,振幅,涨跌%,涨跌额,换手。

## 延迟分三层，各自怎么量

```powershell
bun run scripts/probe-latency.ts     # ①  一起测，结果写 data/probe-latency.txt
```

| 层 | 含义 | 实测（2026-09-20 收盘后） | 谁受影响 |
| --- | --- | --- | --- |
| ① 传输往返 | 本机 → 接口 → 本机 | 7–50ms 中位 | 每轮拉 300 支 = 5 个请求，约 1.2s |
| ② 引擎一轮 | 指数 + 快照 + 打分 + 撮合 | 中位 58ms，首轮 967ms（含拉日历与日线） | 轮询节奏 3000ms |
| ③ 数据新鲜度 | 快照自带时刻距今多久 | 盘中才会接近真值；收盘后就是上一交易日 | **决策与撮合** |

③ 是唯一天真的约束：它由 `quotes.ageSec` 上报，阈值 `QUOTE_STALE_SEC`（默认 30 秒）。
收盘后测的话 ③ 会显示十几万秒，属预期，仪表盘此时改显"收盘 09/18"而不是那个荒谬数字。

## 由数据级别推导出的三条硬规则

### 1. 行情老化就什么都别做

`engine.roundInner()` 里的 `usable` 要求同时满足：交易日 + 可交易时段 + 有快照 + `ageSec ≤ 阈值`。
不满足时：不选股、不出退出单、**也不做影子撮合**。仪表盘顶部亮黄色横幅并报出具体秒数。

拿隔夜价当活价下单，是这类系统最容易犯、也最贵的错。

### 2. 纸面撮合不许美化自己的成交

`orders.settlePending()` + `orders.tryPaperFill()`（整条链路由 `test/settle.test.ts` 钉住）：

- 成交价 = **下一轮观测到的真实对手价**（买吃卖一、卖打买一），不是下单那一刻的现价：
  3 秒里跑掉的价格必须付；`last ± SLIPPAGE_TICKS` 只在盘口整本缺失时兜底使用
- **成交价与成交量都被可见盘口限制**（`bookEating`）：只吃限价档以内的五档，成交价 = 被吃档量的
  加权均价（不是最优档价），深度不够就**只成交一部分**，余量继续挂着。旧模型假设一张单要么
  全部成交要么不成交 —— 那就是把“排队优先权归我们且对手不会跑”当成免费午餐
- 买一/卖一为 0（真没人报）不成交；**限价内没有对手量也不成交** —— 旧实现会“按限价成交”，
  而现实中那张单只会挂在场上等价格回来
- **本轮刚挂的单本轮不成交** —— 人工下单总有秒级延迟，拿建单那一刻的卖一成交等于免掉了这段延迟
- 判"能不能成交"只看挂单之后逐轮观察到的 `seenLow` / `seenHigh`（`updateResting` 累加），
  **不看全天累计高低点** —— 09:31 的最低价不能让你 14:45 挂的单"成交"
- 买被 `limitHigh` 钳住、卖被 `limitLow` 钳住：价格已经跑远就判追价失败
- 一字涨停买不进、一字跌停卖不出；停牌不成交；对手价为 0（真没人报）也不成交
- **当日有效**：隔日单一律作废，收盘后今日单也作废 —— 一张只有当天意义的指令不能第二天还成交
- 买入腿与**卖出腿走同一个 `settlePending`** —— 以前只有买单进队列，退出阶梯（止损/减半/旧到点清仓）
  在影子盘里从未被执行过，那条链路现在是通的（审计发现，已补测）

仍然不建模的：排队概率与成交到达强度（L1 拿不到队列，只能假设“价格到了、限价内有量就轮到我们”，
这在流动性好的标的与小额单上近似成立）、人工从看到建议到下单的真实延迟（现在只计了一个行情切片）。
另外两个口径上的诚实说明：L1 只有五档，超过五档的申报不产生冲击也不会成交；本系统不计冲击
以外的机会成本（追不上就不追，单会作废）。

### 3. 闸门的输入必须与它要否决的那个时刻同口径

成交额节奏闸门的分母是**累计交易分钟**（`session.tradingElapsedMin`，跨过午休不清零）：
当日累计成交额是连续增长的量，下午 13:01 已经交易了 121 分钟。旧实现下午从 13:00 重算，
导致整个午后阈值只有应达值的一半（尾盘 14:40 只需 1250 亿而不是 2750 亿），而 13:00
那一分钟反而要求全天阈值 —— 闸门恰好在它最该起作用的缩量午后形同虚设。
回测的尾盘入场用同一个函数折算（`tradingElapsedMin(14:45)`），两边口径一致。

涨停池只在**连续竞价时段现采**（与决策同节奏，每 `DECIDE_EVERY_MS` 一次），采到才算
`known`；采不到就跳过这一项否决，并把它列入 `gate.skipped` 在面板上显示（`note` 也会写）。
旧实现每天只盘前跑一次，而 09:05 当日涨停数必然是 0 → 这条否决项永远不生效，且结果取决于进程是几点启动的。
「没数据」与「情绪冰点」必须可区分：拿默认 0 去否决会把系统锁死在空仓。

涨停家数本身也是**当日累计量**（一天里只会单调增多），所以它的阈值同样按节奏折算：
`ceil(20 × 已交易分钟/全天)` —— 09:31 只要求 1 家（真的 0 家才是冰点），14:40 要求 19 家。
固定 20 家在早盘几乎不可能达到，那会把“今天能不能买”变成“每天开盘后一小时不准买”——
一个天天发作的永久假阳性（成交额阈值已经按节奏折算过，同一个道理不能漏掉涨停数）。

闸门的结论带时效：`gate.status = open | closed | idle`。`live=false`（收盘后、非交易日、
行情不新鲜）时一律 idle —— 拿着全天成交额与昨日收盘位说“闸门开”，是对下一个交易日的
无意义背书。日志与面板此时写“闸门待命”，`allowed` 仍然输出（盘前预选与复盘靠它），但它不再被伪装成可用开关。
同理，收盘后 `POST /scan` 产生的单只作为“本轮观点”展示，**不进入在途队列**（不落 pending、不会成交）。

## 仍然存在的口径差异

旧日频回测把"次日 10:00 前清仓"记为**收盘价**，实时路径记为下一轮观测到的对手价 ± 限价钳制；
当前生产 Jev 不设固定清仓时点，退出由 Jev 决策；因此这条旧回测口径不能直接代表生产表现。
回测的止损用当日最低价触及判定（不含盘中追价的滑点放大），实盘用逐轮现价比较；
实盘的 VWAP 弱势离场在日线上无法重现（回测里没有这一条腿）。
要消掉这些差异只有两条路：拿到分钟线，或者接券商接口拿真实委托回报。

入场时刻也不同构：回测固定在 14:45（`--select/--stop` 可改参数，但入场点是写死的）；
实盘从 09:30 起每 `DECIDE_EVERY_MS` 就可能出单 —— **同一个硬阈值（3~7% 涨幅、量比 ≥1.5、
成交额 ≥2 亿）在早盘的含义与尾盘完全不同**（成交额是累计值、量比在开盘几分钟内天然偏高）。
用尾盘回测的结论为盘中入场背书，是本项目当前最大的口径缺口。
