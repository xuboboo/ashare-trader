# 数据源、级别与延迟

一句话：**这套系统看到的是 L1 三秒快照，不是 L2 逐笔**。所有关于"能不能做盘中"的判断都由此决定。

## 级别：L1

| 有 | 没有 |
| --- | --- |
| 最新价、买五档 / 卖五档 | 十档全量 |
| 当日累计成交量、成交额 | 逐笔成交（每笔的方向、价、量） |
| 分时均价 VWAP、量比、换手率 | 逐笔委托 / 委托队列（买一后面排了多少手） |
| 涨跌停价、总市值 / 流通市值 | 盘口委托变化的推送 |
| 日线 OHLCV、涨停池、连板数 | 分钟级以下的可靠路径 |

交易所 L1 本身就是 **3 秒一个切片**，这是物理下限，与本机网络、代码效率无关。
平均信息年龄 ≈ 1.5s，最差 3s，再叠加第三方接口的抓取与转发。

## 三个踩过的坑（都有测试或代码兜住）

1. **GBK**：腾讯返回 `charset=GBK`，直接 `res.text()` 会变乱码。`http.ts` 按 `content-type`
   判断编码，用 `TextDecoder("gbk")`（Bun 1.4.2 支持）。
2. **`000001` 歧义**：东财 secid `1.000001` 是上证指数、`0.000001` 是平安银行。用代码前缀推市场
   会把大盘 MA5 算成银行股价格（真踩过）。所有大盘相关一律用 `INDEX_SECID = "1.000001"`。
3. **限流**：`push2his` 在持续 ~2 req/s 后会整体 `ECONNRESET`，且之后连之前成功的代码也失败。
   对策：全局降到 3 req/s + 抖动退避 + **三源回退** + 东财失败后 2 分钟熔断。
   回退源没有成交额，用 `(高+低+收)/3 × 成交量` 估算并打 `amountEst` 标记，
   `fetch-daily` 与 `backtest` 都会报出"多少支是估算的"。

字段序号由 `test/quotes.test.ts` 用 **2026-09-18 真实录制的一行行情**锁死（契约测试）：
上游改字段顺序时测试先炸，而不是让因子静默算错。关键位置：腾讯 `47/48` = 涨跌停价、
`49` = 量比、`51` = 分时均价、`37` = 成交额（**万元**）；东财 `stock/get` `f51/f52` = 涨跌停价；
kline `fields2` 顺序 = 日期,开,收,高,低,量,额,振幅,涨跌%,涨跌额,换手。

## 延迟分三层，各自怎么量

```powershell
bun run scripts/probe-latency.ts     # ①  一起测，结果写 data/probe-latency.txt
```

| 层 | 含义 | 实测（2026-09-20 收盘后） | 谁受影响 |
| --- | --- | --- | --- |
| ① 传输往返 | 本机 → 接口 → 本机 | 7–50ms 中位 | 每轮拉 300 支 = 5 个请求，约 1.2s |
| ② 引擎一轮 | 指数 + 快照 + 打分 + 撮合 | 中位 58ms，首轮 967ms（含拉日历与日线） | 轮询节奏 3000ms |
| ③ 数据新鲜度 | 快照自带时刻距今多久 | 盘中才会接近真值；收盘后就是上一交易日 | **决策与撮合** |

③ 是唯一天真的约束：它由 `quotes.ageSec` 上报，阈值 `QUOTE_STALE_SEC`（默认 30 秒）。
收盘后测的话 ③ 会显示十几万秒，属预期，仪表盘此时改显"收盘 09/18"而不是那个荒谬数字。

## 由数据级别推导出的两条硬规则

### 1. 行情老化就什么都别做

`engine.roundInner()` 里的 `usable` 要求同时满足：交易日 + 可交易时段 + 有快照 + `ageSec ≤ 阈值`。
不满足时：不选股、不出退出单、**也不做影子撮合**。仪表盘顶部亮黄色横幅并报出具体秒数。

拿隔夜价当活价下单，是这类系统最容易犯、也最贵的错。

### 2. 纸面撮合不许美化自己的成交

`orders.tryPaperFill()`：

- 成交价 = **下一轮观测到的现价** ± 滑点（`SLIPPAGE_TICKS`，默认 1 tick），不是下单那一刻的参考价 ——
  3 秒里跑掉的价格必须付
- 判"能不能成交"只看挂单之后逐轮观察到的 `seenLow` / `seenHigh`（`updateResting` 累加），
  **不看全天累计高低点** —— 09:31 的最低价不能让你 14:45 挂的单"成交"
- 买被 `limitHigh` 钳住、卖被 `limitLow` 钳住：价格已经跑远就判追价失败
- 一字涨停买不进、一字跌停卖不出；停牌直接不成交

这四条各自对应 `test/orders.test.ts` 里的一个用例。

## 仍然存在的口径差异

日频回测把"次日 10:00 前清仓"记为**收盘价**，实时路径记为下一轮观测价 ± 滑点；
回测的止损用当日最低价触及判定（人工执行下合理，但不是逐笔可验证的）。
要消掉这个差异只有两条路：拿到分钟线，或者接券商接口拿真实委托回报。
